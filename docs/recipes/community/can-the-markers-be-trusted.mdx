Check every stock behavioral marker against ground truth. `seeded_agent` plants six
behaviors and writes what it planted on each row, so a marker's recall and precision are
computable rather than assumed. The four markers that name a phrase are **perfect** —
recall 1.000 [0.998, 1.000] and zero false alarms over 1,734 planted rows — and that
number is circular, because the generator inserts the exact strings the marker greps for.
The two planted behaviors that are task failures rather than phrases, `ignore_fault` and
`leak`, have **no marker at all**: recall 0.000 [0.000, 0.005] over 807 planted rows.

So **24.2% [22.6%, 25.9%]** of the rows a fully green marker dashboard passes are
carrying a planted failure, and a marker-measured improvement recovers only
**68.1% [66.2%, 69.9%]** of the improvement that actually happened.

What you will learn: what `style_report`'s markers do and do not see, why a detector
validated on `seeded_agent` is validated on itself, and how to put ground truth under a
behavioral metric before you quote it. You need **nothing**: no model key, no GPU, no
network. Six seconds locally; the 12-seed version is about two minutes of CPU on your own
Modal.

## The question

> `compare()` reports a delta on every shared marker beside pass@1, and
> `compare(proxy="marker:X")` will tell you whether the reward is paying for a tic. Both
> take on faith that when marker X moves, behavior X moved. Does it?

Nothing in the ledger had measured it, and there is exactly one place in this library
where a behavior has a machine-checkable gold label: `seeded_agent`'s own docstring says
each row "says what was planted, so a grader **or a marker** can be checked against the
truth." This is that check.

## The setup

- **Ground truth is the plant record**, `row["seeded"]`, not my opinion and not a judge.
  It is a program's label, so it is attached with `attach_labels(..., kind="program")` —
  the one kind `judge_trust` calls measured without `allow_model_gold`.
- **The arms are the same agent at two misbehavior rates**, 0.50 and 0.15, standing in
  for a policy that got better. The point is not that it improved; it is by how much the
  two instruments say it improved.
- **The task grid is written once and pinned with `tasks=`.** Two `simulate` calls at the
  same budget do *not* cover the same tasks — `eval_variance` says so in a note ("runs do
  not cover the same tasks; means are not strictly comparable") — so without pinning,
  nothing is paired. With it, 74 of 74 scenarios pair.
- **The noise floor is three re-runs** of the before arm at different agent seeds, passed
  to `compare` as `run_std_by_metric` so the gold metric and each marker get their own
  band.
- **Both instruments measure the same quantity**: the share of rows with no failure. Gold
  reads the plant record; the marker reads `style_markers`. That is what makes "recovers
  68%" a comparison and not a ratio of unlike things.

## Run it

```bash
uv add whileai
cd recipes/community/can-the-markers-be-trusted
python run.py                                      # 3 seeds, ~6 s, no key
python run.py --dry-run                            # one seed, small budget
python run.py --json results.json --modal-seeds seeds.json
modal run markers_modal.py --seeds 12              # 12 CPU containers on your Modal
```

| flag | default | what it does |
|---|---|---|
| `--seeds` | `0,1,2` | agent seeds; each is an independent draw of which rollouts misbehave |
| `--budget` | 600 | rollout budget for the task grid |
| `--phrasings` | 6 | the knob that actually grows the row count (`budget` alone saturates) |
| `--before-rate` / `--after-rate` | 0.50 / 0.15 | the two arms |
| `--dry-run` | off | one seed at budget 120 |
| `--modal-seeds` | none | fold a `seeds.json` from `markers_modal.py` in as the headline |

`results.json` is the output of the fourth command. `seeds.json` is the output of the
fifth, run on `wai-marker-trust`, 12 CPU containers, 5,064 rows.

`judge_trust` with the marker as the judge agrees: agreement 1.00, kappa 1.00,
`gold_kind=program`, `ok=True` on all four. **This is the least interesting true thing in
the recipe.** `seeded_agent` plants `hedging` by appending `"It depends."`; `no_hedging`
greps for `it depends`. A validation on this generator validates the marker against its
own definition, and says nothing about whether a real model's hedging looks like that
list of six phrases. Any recall you read here is an upper bound that does not transfer.

Read that as a reviewer would: the markers are directionally right and every one of them
understates. Two of the four land inside their own noise band on a change that moved the
gold metric by nearly 40 points. If the markers were all you had, you would report a real
improvement as partly noise.

## The bug this run found

`attach_labels` will write the wrong gold label onto most of your rows and report a clean
match. Runs on a pinned task grid share `(scenario_id, rollout_index)`, which is the key
`attach_labels` matches on, so labels for one run land on every run's rows:

```text
rows=1266  distinct keys=74  labels passed=1266
{'matched': 1266, 'unmatched': 0, 'invalid': 0, 'ties': 0, 'rows_labeled': 74}
rows whose gold_reward != the label passed for that row: 1200
```

Downstream, `judge_trust` reported agreement 0.89 and **kappa 0.00** for a detector whose
true agreement is 1.00, and called three of the four `ok=True`. Filed as
[#759](https://github.com/whilehq/whileai-sdk/issues/759). The recipe stamps a unique
`rollout_id` on every row and asserts `mislabeled_rows == 0` in `results.json`; do the
same before you believe any `judge_trust` number computed over pooled runs.

## What this does NOT show

No claim that `style_report` is wrong about what it measures — it measures phrase
presence and it is exact at that. The claim is about coverage: the marker vocabulary
(`no_boilerplate`, `no_hedging`, `no_apology`, `no_sycophancy`, `answered`) and the
generator's behavior vocabulary (`hedging`, `sycophancy`, `apology`, `boilerplate`,
`ignore_fault`, `leak`) overlap on four names, and the two that do not overlap are the
behavioral ones.

The 24.2% is a property of this generator's mix, not a law: it is roughly the share of
`seeded_agent`'s plants that are `leak` or `ignore_fault` among rows the markers pass.
Change `behaviors=` and the number moves. What does not move is that no setting of
`behaviors=` makes the stock markers see either of them.

Recall is measured; **precision against a real model is not measurable here**, because
`seeded_agent` never writes a phrase it did not plant. Zero false alarms over 5,064 rows
is a fact about the generator. A real model that opens with "Great question!" while
answering correctly would be a false alarm, and nothing in this run bounds how often that
happens.

## Next

Two things. First, **a verifier for the two blind behaviors**: `ignore_fault` is
mechanically checkable (the row carries `faults`, and the reply either states what the
tool returned or does not), and `leak` already has a gate inside `select()` that a
previous run ([#699](https://github.com/whilehq/whileai-sdk/pull/699)) found is good and
unreachable. Both as `extra=` detectors on `mark_rows` would take the 24.2% to zero on
this generator and would be the first markers here that are not phrase lists. Filed as
[#760](https://github.com/whilehq/whileai-sdk/issues/760).

Second, **the same measurement against a real model**, which is the half this one cannot
do: generate on your own Modal with Qwen2.5-1.5B-Instruct, hand-label 200 replies for
hedging, and measure `no_hedging`'s recall against people rather than against its own
phrase list. That is the number that would tell you whether any of this transfers, and it
is the one the seeded path structurally cannot produce.
