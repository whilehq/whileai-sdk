```bash
uv add whileai
```

Python 3.10 to 3.13. Two dependencies, `requests` and `pydantic`. Typed, so an editor shows every knob.

```python
import whileai
print(whileai.__version__)
```

## Extras

| Install | Adds |
|---|---|
| `uv add 'whileai[rl]'` | `verifiers`, so an exported RL environment installs and `load_environment` rebuilds it for GRPO trainers. Python 3.11 to 3.13. |
| `uv add trl transformers` | Your own trainer. `to_trl`, `loss_mask`, `TrainerCallback` and `HackMonitor` work against whatever TRL you install; the SDK does not pin one. |

Everything else, including training on the platform, needs only the base
package.

## Do you need a key?

Not to start. Everything on the [quickstart](/get-started/quickstart)
runs offline: the template situation writer (`simulator=False`), the
built-in `seeded_agent`, your own judge as a function.

A key turns on the hosted parts: the hosted situation writer and judge,
dataset storage, training and serving. Get one from the terminal:

```bash
whileai login
```

That opens the browser, waits for approval, and saves a key on this
machine. No browser? `whileai signup --email you@example.com` creates an
account and a key in one step. Where the key goes, and where a model
string goes, is on [keys and models](/get-started/your-model-and-key).

In code, the same key and any provider key go through `configure`, once:

```python
import whileai as wai

wai.configure(
    api_key="zp_...",                                        # the While account key
    agent=wai.OpenAI("gpt-4.1-mini", api_key="sk-..."),      # or OPENAI_API_KEY
)
print(wai.settings)                                          # says which model and key each role uses
```

[Connect your agent](/get-started/connect-your-agent) has the table of
backends and which key each one reads.
